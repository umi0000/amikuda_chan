# 校园网答疑控制台

AstrBot 插件。按指定群组和时间生成 AI 报告，可选择读取插件独立归档或 AstrBot 已持久化的群聊记录。报告只在 AstrBot WebUI 内查看；不发群、不自动回复，不向消息平台回拉历史。

## 安装与启用

1. 使用 AstrBot **4.29.4 或更高的 4.x 版本**，并使用与核心匹配的 Dashboard。先在 AstrBot 中接通目标消息平台；不限定 SnowLuma 或 OneBot。
2. 将本项目放到 AstrBot 的 `data/plugins/astrbot_plugin_amikuda_chan/`（Docker 环境使用映射的 `data` 目录），使 `metadata.yaml` 直接位于该目录下；然后加载插件。不需要安装额外 Python 或前端依赖。
3. 在 AstrBot 的 **插件 → 校园网答疑控制台 → 插件配置**中设置「允许采集的群」。在会话来源选择器中多选群聊，或在目标群发送 `/sid`，复制 `UMO` 的值（不含两侧书名括号），格式为 `平台实例ID:GroupMessage:会话ID`，例如 `telegram:GroupMessage:-100123456`。不允许私聊或系统消息。OneBot、QQ 官方和 QQ 官方 Webhook 的成员隔离 UMO 会归并为整群；其他平台请选群级 UMO。留空不采集；保存后重载插件。
4. 打开 AstrBot 左侧扩展功能中的 **校园网答疑控制台**，进入「配置」，选择已在 AstrBot 中启用的聊天模型，检查提示词并保存。插件不需要单独的模型 API Key。
5. 回到控制台「首页 → 新建报告」，选择消息来源、群和时间，预览后生成报告。「插件归档」只读取本插件实际收到并保存的文本；「AstrBot 历史」只读取 AstrBot 当前留存的群聊记录，包括安装插件前已保存且尚未被清理的记录。

## 消息来源

- 在每次新建报告的弹窗中选择「插件归档」或「AstrBot 历史」，默认插件归档。两者均限定在插件配置的授权群内；切换来源后必须重新预览，不混合、不在空数据或读取失败时自动回退。
- AstrBot 历史通过其管理的数据库会话进行只读查询，不直接连接数据库文件、不修改核心记录、不把消息正文复制到插件归档。只分析留存的用户文本，排除机器人输出、纯媒体占位符、私聊和未授权会话。OneBot、QQ 官方和 QQ 官方 Webhook 的成员隔离记录按群归并。
- AstrBot 历史按入库时间筛选，引用 `astrbot-<id>` 中的 id 为核心历史记录编号，不是平台消息 ID。它的留存受 AstrBot 的「持久化最大消息数量」控制，默认值可能只够少量天数。不能证明完整覆盖时，预览与报告注明「完整性未知」。
- 预览零条文本时，查看每群说明：未匹配到持久化记录时检查平台实例 ID、群 UMO 和持久化设置；有留存但时段不匹配时参考最早和最晚入库时间；时段内只有非用户文本时不会生成报告。不同平台实例的历史不自动合并。
- 来源只是本次报告的读取选项，不会停止插件已授权群的实时归档，也不会改变 AstrBot 的采集开关。报告永久保存当时的来源、范围和提示词；旧版报告自动标记为插件归档，正文保留。

## 时间和覆盖

- 一份报告可勾选多个已授权群。自定义日期按北京时间计算，包含结束日；「最近 N 天」向前滚动 `N × 24` 小时；「上个自然周」为上周一零点至本周一零点。日期范围最多 366 天。
- 预览不调用模型。没有留存文本就不能生成。报告保存实际时间范围、各群消息量、模型、提示词和当时的覆盖信息。生成较长报告时分段处理，再合并结果；任一请求失败都会标记任务失败，不保存为完整报告。
- 「完整性未知」或「覆盖不完整」只作提示，不禁止生成。预览中有文本且已保存可用的报告模型即可提交；按钮下方显示当前可用状态或明确阻塞原因，未配置模型时可直接跳转配置页。
- 插件归档的覆盖只表示本插件的已知采集时段，不等于平台历史完整性。插件不回拉旧消息，也无法从群内沉默判断消息平台是否曾断线。AstrBot 历史不使用插件的采集起点推断覆盖完整性。
- 消息量是所选来源的实际留存文本计数，问题主题和处理线索由 AI 总结。报告中的 `[G1:消息ID]` 对应详情里的群编号和所选来源的消息编号；AstrBot 来源使用 `astrbot-<记录ID>`，插件来源使用适配器消息 ID。引用与结论仍需人工核对，未建立问题台账，不把推测当成正式解决率。

## 消息管理

- 打开控制台「消息管理」，选择已监控的群和消息来源，可按北京时间的起止日期筛选；日期留空表示全部留存记录。按时间从新到旧分页查看，每页 50 条，显示时间、发送者、正文、消息 ID 及引用信息。浏览不调用 AI 模型。
- 「插件归档」显示插件留存文本，时间为消息时间；「AstrBot 历史」显示核心当前留存的群消息（包括机器人输出及媒体占位符），时间为入库时间。只提供文本查看，不加载媒体文件；AstrBot 历史始终只读。
- 仅插件归档提供清理：「某日之前」删除该日北京时间零点之前的消息，不包含该日；「日期范围」包含结束日全天。清理只允许已结束的日期，避免把未来消息也纳入清理范围。
- 清理前先预览目标群、范围和数量，再确认不可撤销删除。预览五分钟内有效；范围内消息数量变化或插件重载后必须重新预览。清理不删除其他群、AstrBot 记录或已生成报告，也不停止该群后续采集。
- 人工清理的时间段会被记为归档缺口，不再误报完整覆盖；该时段延迟到达的历史消息不会重新写回插件归档。

## 数据和权限

- 插件独立数据位于 `data/plugin_data/astrbot_plugin_amikuda_chan/`。`reports.sqlite3` 存消息、设置和已生成报告。Docker 中应持久化 `data`。
- 群消息正文、发送者 ID 和文本中的 @ 成员 ID 不做脱敏或匿名化，并作为报告分析输入传给所选模型；模型返回内容也不会因匹配到特定文本而被替换。
- 消息正文默认保留 30 天。过期正文会清理，已生成的报告单独保留，不随正文自动删除。旧版归档里已经替换为 `[已脱敏]` 的文本无法恢复；旧发送者代号也无法还原，更新后新消息和 AstrBot 历史才会按原始文本及发送者 ID 读取。

## 开发验证

运行 `python3 -m unittest discover -s tests -v`，验证跨平台采集边界、报告来源隔离、快照范围与旧数据库迁移。该检查不需要连接实际消息平台。
