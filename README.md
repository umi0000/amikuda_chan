# 校园网答疑控制台

AstrBot 插件。实时归档授权群聊中的文本，按指定群组和时间生成 AI 报告。报告只在 AstrBot WebUI 内查看；不发群、不自动回复、不读取安装前的群聊历史。

## 安装与启用

1. 使用 AstrBot **4.29.4 或更高的 4.x 版本**，并使用与核心匹配的 Dashboard。先在 AstrBot 中接通目标消息平台；不限定 SnowLuma 或 OneBot。
2. 将本项目放到 AstrBot 的 `data/plugins/astrbot_plugin_amikuda_chan/`（Docker 环境使用映射的 `data` 目录），使 `metadata.yaml` 直接位于该目录下；然后加载插件。不需要安装额外 Python 或前端依赖。
3. 在 AstrBot 的 **插件 → 校园网答疑控制台 → 插件配置**中设置「允许采集的群」。在会话来源选择器中多选群聊，或在目标群发送 `/sid`，复制 `UMO` 的值（不含两侧书名括号），格式为 `平台实例ID:GroupMessage:会话ID`，例如 `telegram:GroupMessage:-100123456`。会话ID可包含字母、负号、下划线等平台原始标识；不允许私聊或系统消息。OneBot 开启成员会话隔离时，复制的 `平台实例ID:GroupMessage:成员号_群号` 会按该实例的适配器类型还原成整群；其他平台请选群级 UMO。留空不采集；保存后重载插件。
4. 打开 AstrBot 左侧扩展功能中的 **校园网答疑控制台**，进入「配置」，选择已在 AstrBot 中启用的聊天模型，检查提示词并保存。插件不需要单独的模型 API Key。
5. 从授权群的普通成员账号发送不带 `@` 的测试消息。回到控制台「首页 → 新建报告」，选择群和时间并预览覆盖，确认消息计数增加，再生成报告。

插件不依赖 AstrBot 的「持久化群聊消息记录」「群聊消息记录注入上下文」或「主动回复」设置。AstrBot 的白名单、会话开关、限流和其他前置检查仍可能阻止消息进入插件；插件不会禁用已有的 AstrBot 默认回复。

不同适配器须上报 AstrBot 的 `GROUP_MESSAGE` 类型、原始会话标识和消息 ID，插件才能归档。平台不推送的普通消息无法由插件补齐。机器人输出仍忽略，正文仅采集可读文本。

旧版升级：重载前，将插件配置中 `collect_groups` 列表的 `平台实例ID:群号=显示名` 项替换为 `平台实例ID:GroupMessage:群号`。若无法打开配置界面，可编辑 `data/config/astrbot_plugin_amikuda_chan_config.json` 中的 `collect_groups`。同一平台实例和群号的已有消息仍可查询，无需迁移数据库。

## 时间和覆盖

- 一份报告可勾选多个已授权群。自定义日期按北京时间计算，包含结束日；「最近 N 天」向前滚动 `N × 24` 小时；「上个自然周」为上周一零点至本周一零点。日期范围最多 366 天。
- 预览不调用模型。没有留存文本就不能生成。报告保存实际时间范围、各群消息量、模型、提示词和当时的覆盖信息。生成较长报告时分段处理，再合并结果；任一请求失败都会标记任务失败，不保存为完整报告。
- 覆盖只表示插件的已知采集时段，不等于平台历史完整性。插件不回拉旧消息，也无法从群内沉默判断消息平台是否曾断线。统计覆盖会考虑已知的停采、插件停止和保留期限。
- 消息量是本地数据库计数，问题主题和处理线索由 AI 总结。报告中的 `[G1:消息ID]` 对应详情里的群编号和适配器消息 ID；引用与结论仍需人工核对。未建立问题台账，不把推测当成正式解决率。

## 数据和权限

- 插件独立数据位于 `data/plugin_data/astrbot_plugin_amikuda_chan/`。`reports.sqlite3` 存消息、设置和已生成报告；`sender.key` 用于生成单群内稳定的发送者代号。Docker 中应持久化 `data`。
- 不存图片、语音文件和发送者原始 ID。对密码、学号、手机号、邮箱等常见格式做尽力脱敏，但无法识别所有自由文本中的敏感信息。配置外部模型前，应确认群管理授权、告知成员并核对数据政策。
- 消息正文默认保留 30 天。过期正文会清理，已生成的报告单独保留，不随正文自动删除。备份数据库和匿名化密钥时按含群聊数据处理。

## 开发验证

运行 `python3 -m unittest discover -s tests -p 'test_collection.py' -v`，验证非数字群标识、频道范围、平台隔离和 OneBot 成员会话归并。该检查不需要连接实际消息平台。
